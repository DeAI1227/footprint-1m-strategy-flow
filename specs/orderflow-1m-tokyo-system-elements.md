# 訂單流系統：全日全年納入元素總表

約束（本版已鎖定）

- 部署：東京伺服器，目標全日全年無人值守運行
- 主週期：1 分鐘 K 線（所有進場、持倉管理、失效判斷的主時鐘）
- 行情連線：三大所公共 WebSocket 全開——Binance、OKX、Bybit（線性永續）。缺一所視為該所品質降級，不是「以後再加」
- 執行所預設：OKX。Binance 與 Bybit 預設只讀、做共振與鉛滯研究。禁止把任一所的價位直接填到另一所去掛單
- 語言：熱路徑用 Rust；狀態機、校準、維運用 Python。邊界見第 3.4 與第 14.6 節，禁止在 Python 熱路徑解析 WS 或組足跡
- 參數：本文件只列元素與注意事項，數字一律留空，以 `<PARAM>` 標記
- 原則：只納入**足跡圖流派**元素（bid×ask 矩陣、斜對角失衡、堆疊、未完成拍賣、delta/CVD、吸收、當根 POC/VA、tape、DOM 對讀）。Market Profile / TPO、VWAP、Naked POC、形態學、SMC **刪除，不計算、不當座標、不當腳本**。腳本內可關閉權重，但不得用「以後可能用到」把外派接回來

本文件是元素清單與契約，不是參數最優解，也不是獲利保證。

## 0. 系統身分與運行契約

### 0.1 運行模式（必須同時存在，可切換）

- 影子模式：只算信號、不下單，寫入同一套日誌與延遲統計
- 模擬撮合模式：用即時盤口做本地假成交（含部分成交、排隊假設）
- 小資金實盤模式
- 正式實盤模式

注意：三種模式共用同一套特徵與狀態機，禁止「回測一套、實盤一套」。切換必須是配置，不能是分叉程式。

### 0.2 帳戶與倉位模式

- 交易所帳戶識別、子帳戶、統一帳戶 / 經典帳戶
- 單向持倉 vs 雙向（對沖）模式
- 保證金模式：全倉 / 逐倉
- 保證金幣種、USD 等值折算來源
- 合約類型：U 本位永續（主）、若納入幣本位 / 交割必須當獨立宇宙，不可混在同一風險池假裝同一個標的

注意：模式在交易所後台改了而程式假設沒改，是全年運行最常見的默殺。啟動與定時必須向私有 API 核對帳戶模式，不一致則禁止開新倉。

### 0.3 法定時鐘

- 內部主時鐘：UTC
- 伺服器時區：Asia/Tokyo（僅用於維運班次、日誌人類閱讀）
- 交易所事件時間、本地收包時間、處理完成時間三者全部打戳
- NTP / chrony 同步狀態本身是監控元素，不是背景假設

注意：1 分鐘 K 線以交易所事件時間切棒，不以「程式 sleep 到整分」切棒。亂序包、晚到包、重連補洞都會打破 naive 整分計時。

## 1. 時間架構（主週期 1m，其餘由 1m 與 tick 派生）

不另開一套「人眼 5 分鐘圖」當第二套主邏輯。更高尺度全部規定為：由 1m 棒與 tick 滾出來的視窗，避免多週期對不齊。

### 1.1 主棒契約

- 符號：`BAR_1M`
- 對齊：Unix 時間整分 `[t, t+60)`
- 開高低收、成交量、主動買量、主動賣量、成交筆數、第一筆/最後一筆成交時間
- 棒狀態：`forming` / `closed`
- 只有 `closed` 棒可觸發「棒級決策」；`forming` 只允許預警、撤單、風控、追蹤止損
- 收棒寬限：等待晚到成交的 `<BAR_CLOSE_GRACE_MS>`（數字留空）
- 收棒後仍遲到的成交：記入下一根的「修正通道」還是丟棄，必須二選一並記錄（建議：不改已閉合棒，只打 `late_trade` 計數，避免狀態機回溯）

注意：全年運行禁止「收盤後改寫已閉合 1m 棒」。回測若允許改寫，實盤對不齊。

### 1.2 必須同時存在的時間視窗（由 1m / tick 滾出）

這些不是第二套 K 線策略，是 1m 決策的位置座標。

- 最近 `<N_BARS_MICRO>` 根 1m（微觀序列）
- 最近 5 根、15 根、60 根、240 根、1440 根 1m 的聚合特徵（對應 5m / 15m / 1h / 4h / 1d 的統計視窗）
- 交易時段視窗（見 8.4），不是日曆日一種切法就夠
- 滾動成交量視窗 `<VOL_WINDOW_BARS>`
- CVD 重置錨點：時段起點、日界、事件起點（可配置，可並行多條 CVD）

注意：1m 上處處是假突破。沒有更高視窗的位置，失衡堆疊不能單獨開倉。視窗特徵必須在 1m 收棒時一起凍結，形成同一快照。

### 1.3 時段與日界（加密 24h 必備）

- UTC 日界
- 交易所資金費結算時刻（每標的實際時刻表，不可寫死「每 8 小時」當唯一真相）
- 亞洲活躍、歐洲活躍、美洲活躍、重疊時段、極薄時段
- 週末、重大假期（傳統市場休市會改變 BTC 流動性，仍要標記）
- 各所維護窗口、預告停機、指數異常

注意：同一套失衡規則在極薄時段會過密。時段不是美化，是開關與倉位乘數的輸入。

## 2. 交易宇宙

### 2.1 標的清單

- 主宇宙（流動性優先）：例 BTC / ETH / SOL 等，具體名單後填
- 研究宇宙（可算信號、默認禁止實盤）
- 黑名單、白名單、暫時停牌名單
- 每個標的獨立開關：`enabled` / `shadow_only` / `disabled`

### 2.2 每個標的必須拉取的契約規格（啟動時與定時刷新）

- 合約代碼、底層、結算幣
- tick size、lot size、最小名義價值、價格精度、數量精度
- 最大槓桿、維持保證金率、檔位保證金
- 限價單價差限制、市價單保護範圍
- 是否允許冰山 / post-only / reduce-only / GTX / 條件單
- 目前資金費、下次結算時間
- 狀態：交易中 / 交割中 / 下架 / 只減倉

注意：tick size 一變，足跡價位桶會整張錯位。規格變更必須觸發「重建該標的矩陣、取消未成交單、暫停新開倉直到下一個乾淨 1m」。

### 2.3 宇宙過濾（數字留空，元素要有）

- 24h 報價量、深度（最佳 `<N>` 檔名義價值）
- 價差（絕對與相對）
- 最近 `<SPREAD_WINDOW>` 的價差分位
- 異常跳動、指數偏離、標記價格與最新價偏離
- 新上線冷卻期
- 即將下架 / 只減倉

注意：高 beta 迷因幣可留在研究宇宙。全日全年實盤宇宙必須能自動因流動性惡化而降級，不能靠人週一改名單。

## 3. 交易所三軌（資料與執行）

三大所公共行情是常開契約，不是可選插件。每個所獨立適配、獨立 1m 矩陣、獨立 book；上層只比共振，**禁止把三所成交量加進同一張足跡**。

### 3.1 角色

- 執行所（預設：OKX 線性 U 本位永續）：自己的成交組進出場足跡；私有 WS + REST 下單、持倉、資金、對帳
- 共振所 A（預設：Binance USD-M 永續）：公共 WS 必接；1m delta / 失衡方向只做確認或否決
- 共振所 B（預設：Bybit linear 永續）：公共 WS 必接；同上，與 Binance 平級，不是「第三備用」
- 執行所自己的公共行情：必接。即使另外兩所都在，OKX 足跡仍是開倉價位的唯一來源
- 私有連線：預設只開執行所。Binance / Bybit 私有只在未來「該所也成為執行所」時才開，且必須獨立風控池與獨立冪等前綴

### 3.2 每個所必須獨立存在的連線

三大所每一所都要有（名稱以該所 API 為準，適配後輸出同一內部事件）：

- 公共成交流（組該所足跡的唯一主原料）
- 公共深度流（L2 snapshot + incremental）
- 公共 ticker / mark / index / funding
- 公共強平流（若該所提供；沒有則用 OI + mark 偏離推 `liquidation_regime`，並在品質向量標 `liq_stream_missing`）
- 公共 OI（輪詢或 WS，按所能力）
- REST 備用：快照、補洞、合約規格刷新
- 僅執行所：私有訂單、成交、持倉、帳戶；以及 REST 下單 / 撤單 / 對帳

Bybit 適配注意（不得省略）：v5 linear 的 public trade `side` 是 taker 方向還是 maker 方向，必須用官方欄位表寫死在適配測試裡；時間戳單位（秒 / 毫秒 / 微秒）不得與 Binance、OKX 混用同一欄位假設。orderbook 的 snapshot 與 delta 主題分開訂閱，checksum 失敗即重建。

Binance 適配注意：`m` / `isBuyerMaker` 與 Bybit `side`、OKX `side` 三套欄位必須在適配層消失，只輸出 `taker_buy` / `taker_sell`。

### 3.3 跨所對齊元素

- 同一底層（SOL、SUI）在三所的合約代碼映射表（啟動時校驗，缺映射則該所該標的 `disabled`）
- 三所各自的 1m 主動買賣方向、delta 正負、堆疊方向
- 共振規則（數字留空，邏輯先鎖）：
  - `k_of_n`：執行所方向為準，另外兩所中至少 `<RESONANCE_K>` 所同向才算確認
  - `all`：兩所共振所都必須健康且同向
  - `off`：仍計算、仍記日誌，不參與開倉確認
- 任一共振所資料不健康：該所本根標記 `not_evaluated`，不得用過期的上一根假裝同向
- 價位換算：不同 tick、不同合約乘數；共振比的是**方向與制度**，不是同一價格數字
- 延遲：各所事件時間、本地收包、特徵完成，分所打戳
- 三所時鐘差、序列缺口、短暫「各走各的」旗標（SUI 上更常見）

注意：禁止把 Binance 或 Bybit 的支撐價直接當成 OKX 的限價價位。跨所使用方式只有三類，必須在配置裡顯式選一種：

1. 僅共振過濾（k_of_n 或 all，見上）
2. 僅鉛滯研究（影子模式統計三所先後，實盤不自動跟）
3. 明確的跨所價差策略（本系統主路徑不以此為主；若開啟必須獨立風控池，且每一腿都在自己的所裡定價）

預設主路徑：**OKX 自己的 1m 足跡做進出場，Binance 與 Bybit 只做確認或否決。** 「看 A 打 B」不得成為未聲明的隱含行為。

注意：東京對三所公共行情的延遲不同，不自動等於對 OKX 撮合有優勢。持倉週期若是數根到數十根 1m，毫秒共址不是 alpha 來源，只是穩定性與丟包率問題。三所全斷或執行所單斷：禁止開新倉；僅共振所單斷：按 `k_of_n` 降級或否決，不得改去用斷線所的快取方向。

### 3.4 語言邊界（Rust 熱路徑 / Python 決策層）

速度與正確性綁在同一條熱路徑上：三所 WS 解碼、L2 重建、1m 足跡、收棒，必須在 Rust 裡完成。Python 不准在生產熱路徑上 `json.loads` 行情、不准用 pandas 組矩陣。

必須用 Rust：

- 三所公共 WS 連線、ping/pong、訂閱、重連、原始 frame 解碼
- 成交正規化、L2 apply、checksum、book 凍結
- 事件時間切 1m、足跡矩陣、棒級匯總、品質向量（含分所）
- 執行所私有 WS 解碼（訂單 / 成交 / 持倉）
- 可選但預設納入：下單 / 撤單的連線寫出與 ACK 解析（風控緊急單走同一條，避免 Python GIL 卡住撤單）

必須用 Python（可迭代、參數與腳本會變）：

- 腳本 A–G 狀態機、確認/否決組合、收盤決策快照的「句子」層
- 參數檔載入、宇宙開關、影子統計、日報
- REST 對帳編排、告警通道、systemd 包裝
- replay 驅動與校準筆記本（呼叫的仍是同一套 Rust 特徵代碼）

交接契約：Rust 在每根 1m **closed** 時產出凍結快照（零拷貝或一次序列化）。Python 只讀這張快照做句子判斷，再把意圖（限價、量、失效價）交回 Rust 執行閘道。forming 棒上的撤單與 kill switch 不經過 Python 決策迴圈。

禁止：熱路徑雙寫一份 Python 足跡「先跑著」。研究用 Python 重放也必須綁 Rust 擴展，否則回測與實盤會分叉。

## 4. 原始資料元素（tick 級，進記憶體）

每一筆原始事件都要能重放。

### 4.1 成交（組足跡的唯一主原料）

- 成交價、量、時間、成交 ID、是否買方為 maker（或等價 taker 方向）
- 是否為強平、ADL、區塊成交（若欄位存在）
- 本地收包時間、缺口標記

注意：方向欄位各所定義不同，必須按所做適配層，輸出統一的 `taker_buy` / `taker_sell`。適配錯誤會讓整個學派反號。

### 4.2 深度 L2

- 快照 + 增量
- 每檔價、量、（若有）訂單筆數
- 校驗和 / 序列號
- 本地 book 健康：checksum 失敗次數、重建次數、凍結標記

注意：增量丟包後的 book 是有毒輸入。book 不健康時：盤口類特徵全部作廢，相關腳本禁止開倉，已掛的盤口依賴單一律撤。

### 4.3 標記價 / 指數 / 最新價

- last、bid1、ask1、mark、index
- 標記價與 last 的偏離
- 指數成分異常標記（若可取得）

注意：強平與保證金看 mark，不是 last。訂單流讀 last/足跡，風控必須同時看 mark。兩者打架時風控優先。

### 4.4 持倉量、資金費、基差

- OI 絕對值、1m 變化、加速
- 預測資金費、實際資金費、結算倒數
- 期現基差或永續相對指數溢價

### 4.5 強平與爆倉流

- 強平價、量、方向、時間
- 1m 聚合強平買/賣名義價值

注意：清算瀑布期間，足跡上的「巨量主動單」優先解釋為被迫平倉，在狀態機裡要有獨立旗標 `liquidation_regime`，壓制「主力建倉」類腳本。

### 4.6 私有流

- 訂單受理、拒絕、部分成交、完全成交、撤銷、過期
- 帳戶餘額、未實現、已實現、維持保證金率、強平價
- 手續費、返傭、實際成交是 maker 還是 taker
- 持倉數量、開倉均價、槓桿

## 5. 1 分鐘足跡矩陣（學派核心，全部計算）

每根已閉合 1m、每個標的一張矩陣。價位軸用「價位桶」，不是盲目 1 tick（加密 tick 過密時 1 tick 會讓失衡失去意義）。桶寬是參數，本版不填。

### 5.1 矩陣單元（每個價位桶）

- 主動買量、主動賣量
- 主動買筆數、主動賣筆數
- 最大單筆買、最大單筆賣
- 量的分位桶（碎單 / 中單 / 大單，分位閾值留空）
- 該桶第一筆與最後一筆時間（用於不平衡的時間結構）
- 該桶是否觸及當根 high / low

### 5.2 棒級匯總

- delta、絕對量、delta 占比
- 主動買量、主動賣量
- 成交筆數、每秒筆數峰值、每秒名義價值峰值（tape speed）
- 當根 POC（成交量最大桶）
- 當根 VA 上沿 / 下沿（`<VALUE_AREA_PCT>`，scope=bar；Orderflows 棒內 70%，禁止做成日盤 TPO）
- high 桶、low 桶的買賣結構（給未完成拍賣、excess 用）
- 上影 / 下影的量與 delta（不是只有價格影線）

### 5.3 失衡

- 斜對角買失衡：`ask_vol(P) vs bid_vol(P - 1 bucket)`
- 斜對角賣失衡：`bid_vol(P) vs ask_vol(P + 1 bucket)`
- 失衡比率、是否超過 `<IMBALANCE_RATIO>`
- 連續同向失衡的堆疊長度、堆疊起迄價、堆疊總量、堆疊內最大單檔比率
- 反向失衡（同一根裡多空兩邊都堆疊）標記——通常視為混亂棒，禁止當乾淨信號

注意：同一根 K 線左右兩側同時堆疊，不是「雙向都強」，是拍賣未決。此棒可記錄，不可開倉。

### 5.4 未完成拍賣

- 當根最高桶是否缺少對向收尾成交（定義參數留空）
- 當根最低桶是否缺少對向收尾成交
- 未完成拍賣是否落在更高視窗的關鍵位上（見 6：堆疊區 / 近根 POC / 近窗量堆 / 擺動）

注意：1m 未完成拍賣極多。元素要算，但預設只有「落在關鍵位」才進入腳本，否則只入日誌。

### 5.5 Excess / 尾端拒絕

- 高點 excess、低點 excess
- excess 的量是否高於 `<EXCESS_VOL_REF>`（留空）
- 薄量滑出 vs 厚量拒絕（兩種都要標，用法相反）

注意：薄量 excess 幾乎無記憶，禁止當支撐阻力。

### 5.6 吸收 / 衰竭 / 發起

每根 1m 相對前 `<ABSORB_LOOKBACK>` 根比較：

- 發起：大 delta 且價格向 delta 方向推進超過 `<INITIATIVE_MOVE>`
- 吸收：主動攻擊量在高分位，價格推進不足，或收在對向
- 衰竭：連續同向推進中，delta 仍高或創新高，但每根淨推進遞減，隨後出現對向失衡或 excess
- 無效標籤：資料不健康、強平制度、價差過大時強制 `unknown`

注意：吸收不是底部確認。狀態機必須允許「吸收 → 第二次打穿」為一等情節。

### 5.7 大單與碎單結構

- 當根大單占比
- 大單方向是否與棒方向一致
- 切片特徵：同向極多筆、單筆很小、時間很密

注意：加密預設大量拆單。「看見一筆巨鯨」不可作為必要條件。

### 5.8 套牢（失敗延伸）的 1m 序列元素

需要跨多根 1m，不是單根矩陣能單獨完成：

- 前區間上沿 / 下沿（區間定義見 6.4）
- 是否有一根或多根 1m 收在區間外
- 是否在 `<TRAP_BARS>` 根內收回區間內
- 被困側的累計 delta、被困側失衡堆疊是否還在區外

## 6. 位置只來自足跡自己（給 1m 腳本當座標）

全部由同一張 1m 足跡矩陣派生。可按視窗並行多份近窗量堆。

**本節不計算：** 日盤 Market Profile / TPO、Initial Balance、Naked / Virgin POC、D/P/b 形狀、VWAP / AVWAP / σ 帶。那些不是本派。

### 6.1 失衡堆疊區（主座標）

- 已閉合、已離開的同向堆疊：起迄價、總量、方向、生成棒
- 回踩是否觸及區沿
- 失效後從候選移除（收在區外且反向 delta 主導，或區內牆被真吃穿）

注意：沒有「離開」就沒有位置，只有當根顏色。

### 6.2 當根 / 近根 POC 與當根 VA

- 當根 POC
- Aligned POC：連續兩根 POC 同價
- 當根 VA 沿（`<VALUE_AREA_PCT>`，**只對該 1m 棒**）
- 最近 `<N_BARS_MICRO>` 根的 POC 簇

### 6.3 近窗量堆（多根足跡桶加總，仍是 footprint）

視窗：最近 5 / 15 / 60 / 240 / 1440 根 1m、時段窗。每一窗只輸出：

- 該窗成交量最大的桶（近窗 POC）
- 厚量帶：連續高量桶的起迄（用分位或相對鄰桶，**禁止** Dalton 兩排 70% 日盤算法，也禁止 Naked POC 清單）
- 量是否仍在舊堆、還是已在新價堆積

注意：加密沒有 RTH。切不同根數會得到不同量堆，這是時鐘選擇。不要發明神聖日線 POC，不要對近窗量堆做 D/P/b 分類。

### 6.4 擺動與區間（只給套牢腳本）

由 1m 高低用客觀規則生成（參數留空），避免 SMC：

- 擺動高 / 擺動低（`<SWING_N>`，Orderflows 教材起點為 5）
- 目前區間：最後一個被接受的高低邊界
- 區間內時間、區間內成交量
- 突破嘗試次數、失敗突破次數

注意：不另算 poor high / poor low。極端收尾只走未完成拍賣與 excess。結構元素的唯一用途是給腳本當關鍵位，不要另外做形態學開倉。

### 6.5 量堆被接受 / 假離開（不是價值遷移學派）

- 價格離開舊堆疊區或舊近窗量堆後，連續 `<ACCEPT_BARS>` 根 1m 的 POC 或桶量在新價堆積 → 舊沿可當回踩座標
- 立刻縮回、外面沒堆量 → 假離開，走腳本 C，不走腳本 D

## 7. 盤口元素（L2，與足跡對讀）

足跡是已打掉的流動性；盤口是還掛著、可撤的流動性。全日全年系統若只做足跡、不做 book 健康與牆行為，缺的是這一派資訊量最大的一半。

### 7.1 靜態深度快照（每個 1m 收盤切一刀，tick 級另做事件）

- bid1/ask1、價差、價差佔比
- 近端 `<BOOK_LEVELS>` 檔累計名義價值
- 買賣深度比
- 最大牆價位、牆名義、牆距中價距離
- 牆是否正好落在足跡堆疊區 / 當根 POC / 當根 VA 沿 / 近窗量堆沿

### 7.2 牆的行為（比靜態牆重要）

對每個被追蹤的牆：

- 生成時間、補量、減量、完全撤銷
- 價格靠近 `<WALL_APPROACH>` 時是補還是撤
- 牆被真實成交啃食的量（必須用成交去核對，不能只看深度變少——深度變少可能是撤單）
- 冰山推論：可見量小，但該價位累計成交遠超可見量且牆反覆補

注意：靜態大牆預設視為布景。只有「靠近時補 + 成交真啃得動或真接得住」才能進入腳本。

### 7.3 盤口與足跡對讀旗標（每根 1m 必出）

- 真吃牆突破：價格穿越牆，足跡主動量對得上被啃的掛單
- 讓路突破：牆先撤，足跡空，價格飄過
- 吸收牆：主動攻擊打在牆上，價格不穿，牆未撤或在補
- 假牆陷阱：攻擊開始後牆撤，價格加速穿過

### 7.4 不可用條件

- checksum 失敗、重建中、深度檔數不足、價差超過 `<MAX_SPREAD>`
- 快照過舊超過 `<BOOK_STALE_MS>`

此時盤口腳本全關，足跡腳本是否降級由配置決定（建議：只允許減倉與平倉，不開新倉）。

## 8. 加密特有制度元素（必須納入，否則足跡會讀錯）

- `liquidation_regime`：短窗強平名義價值、OI 急降、價格單向加速
- `funding_crowding`：資金費絕對值、持續時間、與 CVD 同向擁擠
- `basis_stress`：標記價偏離、指數偏離
- `oi_divergence`：價新高/新低而 OI 下降或上升
- `fee_regime`：目前 taker/maker 費率、是否在促銷、實際成交費率
- `latency_regime`：收包延遲分位、重連、交易所過載（錯誤碼、拒單）
- `news_or_halt_regime`：可先做手動旗標與維護旗標；自動新聞可後期再加，但「暫停新開倉」開關必須先有

注意：清算制度下，禁止把堆疊失衡解釋成建倉鐵板。擁擠制度下，順向追擊腳本必須降權或關閉。

## 9. 交易腳本狀態機（足跡圖流派用法，可獨立開關）

同一時間每個標的只允許一個**主腳本**處於 `armed` 或 `in_position`。其他腳本可處於 `watch`，只能否決或加確認，不能同時開反向倉（除非明確開啟對沖模式且獨立風控，預設關閉）。

每個腳本統一生命週期：

`inactive → watch → armed → executed → manage → exit → cooldown`

每個腳本必須有：進場條件、確認項、否決項、失效條件、禁止重入時間。數字留空。

### 9.1 腳本 A：失衡堆疊區回踩

- 元素：閉合 1m 出現同向堆疊；價格離開堆疊區至少 `<LEAVE_BARS>` 或 `<LEAVE_DISTANCE>`；回踩觸及區沿；觸及時出現對向拒絕（excess、吸收、或對向失衡）；盤口未出現同向讓路
- 失效：收盤在區外且反向 delta 主導；或區內牆撤且被真吃穿
- 注意：當根追價掃堆疊不是此腳本。沒有「離開」就沒有回踩。

### 9.2 腳本 B：關鍵位吸收反轉

- 元素：位置在堆疊區沿 / 近根 POC / 近窗量堆沿 / 擺動高底；攻擊量高分位；推進失敗；對向 excess 或對向堆疊
- 失效：同向第二次攻擊打穿且 OI/強平不解釋為唯一原因時仍破位
- 注意：真空地帶的吸收只記錄，不開倉。

### 9.3 腳本 C：失敗突破 / 套牢反向

- 元素：客觀區間；收在區外；`<TRAP_BARS>` 內收回；區外留下被困側量與未完成拍賣
- 失效：再次收在區外並被接受（外面開始堆量）
- 注意：1m 假突破極多，必須有區間與收回，不能單根長影線。

### 9.4 腳本 D：量堆被接受後回踩舊沿

- 元素：新價位已連續堆積（6.5）；回踩舊堆疊沿或舊近窗量堆沿；1m 拒絕
- 失效：縮回舊堆且新 POC 放棄
- 注意：這是偏慢腳本，用閉合 1m 做，不需要 tick 搶單。不要寫成回踩舊 VAH。

### 9.5 腳本 E：趨勢衰竭結束

- 元素：同向主動連續；推進遞減；CVD 背離（視窗要聲明）；對向堆疊或吸收
- 失效：衰竭後再次發起並創新高/新低且 CVD 跟上
- 注意：允許「衰竭多次」。第一次衰竭預設只減倉或只平倉，是否反手用獨立開關，建議默認不反手。

### 9.6 腳本 F：盤口真吃牆順突破

- 元素：牆被成交核對為真吃；1m delta 同向；更高視窗不在極端擁擠清算中
- 失效：吃牆後後續 1m delta 立刻消失且收回牆內
- 注意：讓路突破走否決，不走此腳本。

### 9.7 腳本 G：未完成拍賣回補（僅關鍵位）

- 元素：關鍵位未完成拍賣；後續未延伸；回補至該端
- 失效：同向延伸被接受
- 注意：非關鍵位未完成拍賣只記錄。

**已刪（不是本派，不要再加開關）：** 腳本 H Naked POC 磁鐵、腳本 I VWAP 偏離回歸。

以上 A–G 全部納入代碼與日誌。實盤初期建議只開 A/B/C/D 的影子，E 只平倉不反手，F 需 book 健康。這是開關策略，不是從清單把外派接回來。

## 10. 確認項、否決項、制度過濾（所有腳本共用）

開倉前必須產出一張凍結快照，欄位齊全，即使沒用到也留空值與 `not_evaluated`。

### 10.1 確認（加分，不可單獨開倉）

- 執行所 1m delta 為準，Binance / Bybit 按 `k_of_n` 或 `all` 同向（不健康的所計 `not_evaluated`，不得用舊棒充數）
- 盤口近端深度比同向
- 位於近窗量堆或當根 VA 有利側
- 回踩落在已標記的堆疊區內
- tape speed 進入高分位但非清算制度
- 非極薄時段

### 10.2 硬否決（有一個就不開新倉）

- 資料不健康（成交缺口、book 壞、時鐘漂移、重連後未暖機）
- 價差過大、深度過薄、標的停用
- 反向主腳本已在管倉
- 處於 cooldown、日虧熔斷、連虧熔斷、總曝險滿載
- 帳戶模式不符、保證金緩衝不足
- 清算制度（對逆勢接刀類腳本必否決；對順勢腳本可配置，預設也否決新開倉，只允許管理已有倉）
- 交易所維護、只減倉、API 限頻
- 當根 1m 為混亂棒（雙向堆疊、極端 wicks 且量結構矛盾）
- 即將資金費結算的 `<FUNDING_BLACKOUT>` 窗口（方向與擁擠同向時尤其要關）

### 10.3 暖機

- 進程啟動、重連、重建 book、補 1m 歷史之後，必須經過 `<WARMUP_BARS>` 根乾淨閉合 1m 才允許 `armed`
- CVD、近窗量堆、擺動結構未就緒則否決

注意：全年運行的崩潰多半發生在重連後的前幾分鐘。暖機是一等公民，不是邊角。

## 11. 進出場、訂單與執行元素

### 11.1 進場方式（每腳本聲明允許哪些）

- 限價掛在結構沿（預設優先，貼近學派「回踩」）
- post-only / maker
- 限價轉 taker（超時未成）
- 市價（僅風控平倉與極少數腳本，預設不開倉用）
- 冰山 / 拆單（可選）

### 11.2 訂單生命

- 客戶端冪等 ID
- 超時撤單 `<ENTRY_TTL>`
- 部分成交後的剩餘處理：撤剩餘 / 改量 / 視為已進場按實際量管倉
- 改價次數上限，防止追價追成市價
- 被拒單原因分類：精度、價差限制、倉位限制、風控、限頻
- 未成交、已報未確認、本地與交易所狀態機不一致時的處理

### 11.3 滑點與保護

- 最差可接受價 `<MAX_SLIPPAGE>`
- 相對 mark 的保護
- 下單時若 bid/ask 已離開信號快照超過 `<SIGNAL_STALE>`，取消執行
- 成交後實際滑點記入該腳本統計，供日後填參數，不在本版填數字

### 11.4 持倉管理（1m 閉合時決策，tick 只做風控）

- 初始止損：結構失效價，不是固定百分比（百分比只當硬上限保險，見 12）
- 移動止損：堆疊沿、近窗量堆沿、當根 VA 沿、擺動
- 分批減倉目標：對側堆疊沿、對側近窗量堆、區間另一端
- 時間止損：持有滿 `<MAX_HOLD_BARS>` 仍未走結構則退出
- 反手：預設關閉；若開啟必須先平後開，中間對帳

注意：超窄固定百分比止損不納入為主止損。可納入為「災難保險」，且必須考慮手續費與最小跳動，否則保險本身會被噪音打掉。

### 11.5 手續費與盈虧會計

- 預估費、實際費、資金費（持倉跨結算必須計入）
- 以「扣費後期望」決定是否允許該腳本在該標的開倉（費率過濾元素，閾值留空）
- maker/taker 實際佔比監控：若腳本設計為 maker 卻大量變成 taker，自動降級該腳本

## 12. 風控元素（全日全年的生命線，獨立於信號）

風控進程必須能在特徵進程卡死時仍平倉或撤單。建議獨立心跳；最低限度也要有同步的硬熔斷。

### 12.1 帳戶級

- 最大名義曝險、最大槓桿、最大保證金使用率
- 距強平距離緩衝 `<LIQ_BUFFER>`
- 日虧、週虧、連虧筆數、連虧金額
- 日交易次數上限（防止錯誤迴圈）
- 總回撤暫停
- Kill switch：撤全部、平全部、只減倉、完全停止

### 12.2 標的級

- 單標的上限、相關標的合計上限（BTC/ETH 同向風險）
- 單筆風險（結構止損距離 × 倉位 × 合約價值）
- 同時開倉腳本數
- 異常波動熔斷：1m 真實波幅超過 `<ATR_HALT>` 則停止新開倉

### 12.3 系統級

- 資料延遲、WS 斷線、私有流沉默
- 本機 CPU、記憶體、磁碟、檔案描述符
- 時鐘偏移
- 連續拒單、連續下單失敗
- 對帳失敗
- 部署區網路分區

### 12.4 倉位公式元素（數字不填，公式要先定）

倉位必須由風險反推，不得先定張數再看止損。

```
risk_capital = equity * <RISK_PCT>
stop_distance = |entry - invalidation|
position_notional = risk_capital / stop_distance * price   # 再換成張數並按精度截斷
position_notional = min(position_notional, symbol_cap, account_cap, leverage_cap)
```

再乘：

- 時段流動性乘數
- 資料品質乘數（非 1 就只允許縮小）
- 腳本權重乘數
- 擁擠 / 清算制度乘數（可為 0）

注意：止損很近時反推倉位會變極大，必須被 `symbol_cap` 與槓桿帽剪掉。這是超窄止損在系統裡最危險的放大機制，必須在元素層就擋死。

## 13. 狀態持久化、對帳與崩潰恢復

全日全年不允許「重啟後忘記自己有單」。

### 13.1 必須持久化

- 每個標的狀態機、當前腳本、信號快照 ID
- 本地活動訂單表、持倉表、已實現當日帳
- 最後處理的成交 ID / 深度序列
- 已閉合 1m 特徵（至少足以暖機的窗口，不必無限）
- kill switch 狀態（重啟不得自動解除，除非明確配置）

### 13.2 對帳

- 啟動時 REST 拉持倉、未成交單、餘額，與本地比
- 定時對帳 `<RECONCILE_EVERY>`
- 不一致：禁止開新倉，告警，按「交易所為真」修復本地，超限則進入只減倉
- 幽靈單、漏單、重複單檢測

### 13.3 重放

- 原始事件落盤（至少成交 + 私有回報；L2 全量可能極大，需分級：全量 / 抽樣 / 只存快照）
- 用同一套代碼從落盤重放 1m 特徵，作為事故調查與之後填參數的基礎

注意：L2 全量全年可能把磁碟打爆。必須有保留策略：熱資料天數、壓縮、降採樣。這是運行元素，不是事後才想。

## 14. 東京伺服器與程序架構元素

### 14.1 部署假設

- 區域：ap-northeast-1 或等價東京機
- 單機先跑通；進程拆分如下，即使同機也要分開崩潰域

進程（邏輯進程，不必一開始就多主機）：

1. 行情接入與校驗（Rust：Binance + OKX + Bybit 三條公共 WS）
2. 特徵 / 1m 矩陣（Rust，三所各算各的）
3. 決策狀態機（Python 讀凍結快照）
4. 執行網關（Rust，預設只打 OKX）
5. 風控 / kill switch（Rust 熱路徑；Python 只更新限額配置）
6. 持久化與日誌
7. 對帳與健康（Python 編排 REST，比對 Rust 本地單簿）

注意：決策可以短暫重啟；執行與風控不能「一起卡死還以為沒倉」。最低要求：風控能在決策掛掉時撤單並視配置平倉。三所 WS 任一路崩，只降該所品質，不得讓一條阻塞解碼拖死另外兩條（分任務或分執行緒，有界佇列，滿則丟行情並打 `gap`，禁止無界積壓）。

### 14.2 連線與限頻

- WS ping/pong、超時、指數退避重連、最大重連頻率
- REST 權重預算、排隊、優先級（風控單 > 撤單 > 平倉 > 開倉 > 查詢）
- IP 白名單、API key 權限最小化（交易與讀取分離若該所支援）
- 密鑰不進日誌、不進特徵檔

### 14.3 時間與效能觀測

- 事件時間到特徵完成
- 信號到報單
- 報單到 ack
- ack 到成交
- 佇列堆積深度
- 1m 收盤後決策是否在下一根開盤前完成（完不成要降載，不得邊算邊漏棒）

注意：漏棒比慢更致命。忙不過來時的降載順序必須寫死：先停研究宇宙，再停低權重腳本，再開倉，最後才動平倉與風控。

### 14.4 監督運行

- systemd / supervisor / 同等物
- 自動重啟、崩潰次數熔斷（短時間反覆崩潰則停止並告警，不要死循環打 API）
- 日誌輪轉、磁碟水位
- 核心轉儲、未捕獲例外上報

### 14.5 發布與配置

- 配置熱更新範圍：宇宙開關、腳本開關、風控數字（數字後填）
- 策略邏輯更新必須版本號，舊信號快照標明版本
- 禁止在實盤進程裡手動改記憶體狀態當修復（除 kill switch）

### 14.6 Rust / Python 進程與介面

- 首選：單一進程，Rust 開多執行緒吃三所 WS，PyO3 釋放 GIL；Python 只在 1m 收盤被叫醒
- 可選拆進程：Rust `orderflowd` 經 Unix socket / shared memory 吐凍結快照。拆進程時必須有心跳，Python 死掉不能阻止 Rust 風控平倉
- 快照格式版本化（例如 postcard / capnproto）。欄位增減要能讓舊 Python 拒絕啟動，而不是默默錯位
- 基準測試契約：單所 SOL 成交高峰時，事件到矩陣更新的延遲分位要進監控；三所同時高峰不得漏 OKX 執行所的棒

## 19. 注意事項總束（補足、全部當成契約）

1. 1m 是主時鐘，不是唯一資訊。位置來自堆疊區、當根 POC/VA、近窗量堆、擺動；執行與失效看閉合 1m；tick 只負責資料、盤口行為與風控。

3. 單因子不開倉。堆疊、CVD 背離、POC、大牆任何一個單獨出現都不足夠。
4. 失效條件與進場條件同級，缺失效定義的腳本不得 `enabled`。
5. 止損對齊結構；固定百分比只當保險帽。止損過近時倉位反推公式必須被上限剪斷。
6. 清算、洗量、假牆、拆單視為常態。
7. 看 A 打 B 不得隱含開啟。預設 OKX 自算足跡；Binance 與 Bybit 全年接公共 WS，只用方向共振或研究。
8. 重連暖機、對帳、kill switch、資料中毒降級，優先於任何 alpha。
9. 已閉合 1m 不得事後改寫。晚到成交只計品質，不回溯開倉。
10. 忙時降載順序寫死，漏棒時停開倉不停風控。
11. 影子模式與實盤同一代碼。參數未填階段只允許影子或模擬。
12. 全年運行的最大敵人是狀態不一致與靜默資料損壞，不是少算一種失衡比率。
